## Fixes after audit 1 (2026-09-23, `mission/audits/gradegoal-audit-1.md`)

Re-verified with all four commands after every fix batch: `npm test`, `SITE=... BASE=/gradegoal npm run build`, `BASE=/gradegoal npm run test:e2e`, `npm run build`. Final run: **`npm test` → 57/57 passing (4 files)**; **`BASE=/gradegoal npm run build` and plain `npm run build` → 41 pages, 0 errors, 0 warnings**; **`BASE=/gradegoal npm run test:e2e` → 148/148 passing** (18 flow tests across `flows.spec.ts` + the full smoke/axe/viewport suite across all 26 routes in `tests/routes.json` plus 5 base routes, light and dark).

### Fixed

- **[P0-1] Hydration mismatch in every island (share links / saved data showed the wrong UI).** `FinalGrade.tsx`, `Gpa.tsx`, `Planner.tsx`, `GradeBook.tsx` and now `Converters.tsx` all used to read `window.location`/`localStorage` inside their initial `useState()`, which the server never sees — Preact then hydrated real, different state onto the SSR-default DOM (wrong inputs, wrong selected tab, mismatched rows), while the visible *result* was silently computed from the real state. Fixed by rendering the same static defaults on the first client render as the server, then applying the real URL/localStorage state in a `useEffect` that runs strictly after mount (a normal re-render, not a hydration diff). Each island now also exposes `data-hydrated="true"` once that effect has run, and the e2e tests wait on it before interacting — this also fixes the flaky "click lands before the island is interactive" race that was failing the grade-book flow test. Added non-default-URL regression tests for every tool in `tests/e2e/flows.spec.ts` (previously the share-link tests only used default-valued URLs, so they passed without testing anything).
- **[P1-1] Dark mode contrast (32 axe `color-contrast` failures).** Added a `--link` token, separate from `--accent` (kept for filled-button/tab backgrounds, which have their own contrast-checked light text). Light mode: `--link` = `--accent` (already ≥4.5:1). Dark mode: `--link` = `#a5b4fc`, which measures 7.6–9.3:1 on `--bg`/`--bg-elevated`/`--bg-muted` (vs `--accent`'s own 2.5–2.9:1). Applied to links, the eyebrow, the active tab, the summary-strip numbers, `.link-card h3`, `.share__status` and the `--focus` ring (also flagged as too faint). Verified with the full light+dark axe run across all 41 routes — 0 serious/critical violations.
- **[P1-2] GPA scale switch silently dropped courses not on the new scale.** Switching scales now remaps every course's grade to the closest grade on the new scale by relative position (`points / scale.max`), instead of leaving it unresolved and excluded. A visible "*n* of *m* courses counted" indicator was added so any genuinely-uncounted row (0 credits, or an unrecognised imported/shared grade) is never silent. Also fixed the same silent-drop bug in every `/gpa-scale/{slug}/` page's embedded "Try it" widget, which preset a scale but never remapped the starter courses' grades — e.g. the Spain page showed "0 of 3 courses counted" before this fix.
- **[P1-3] GPA row grade `<select>` collapsed to a bare chevron at 320px.** The inline `style="grid-template-columns:…"` on the GPA item row overrode the shared `.item-row`'s `@media (max-width:560px)` rule. Moved it into its own `.item-row--gpa` class with its own mobile breakpoint (mirroring the grade-book rows, which were already correct).
- **[P1-4] Grade book: reloading/sharing a saved course duplicated it on the next Save and lost the term.** The saved course's own state was (correctly) mirrored into the URL for shareability, but on reload that made it indistinguishable from an externally shared link, so it always became a disconnected `'draft'`. The URL now also carries the saved course's `id` and `term`; on load, a matching id reopens the actual saved course instead. Also added: a confirmation dialog before "Delete course", and a confirmation before switching/creating a course when the current one has unsaved changes.
- **[P2-1] Typing a decimal (e.g. "0.5") into a number field got corrupted ("0.015", or cursor jumps producing "50").** Two layered causes, both fixed: (a) fields with a `min > 0` (weight, weight1/weight2, tests'-share) clamped up to that minimum on every keystroke, so an in-progress "0" got rewritten to "0.01" mid-typing — clamping moved from `onInput` to `onBlur`. (b) even without that, any number input whose `value` is bound straight to numeric state gets its DOM value forcibly reset on every render, which drops a just-typed trailing "." and can reset the caret — added `src/components/islands/numberField.ts`, a small hook that keeps the input uncontrolled and only ever syncs it imperatively when it is *not* the focused element. Applied throughout `FinalGrade.tsx` and `Planner.tsx` (every top-level numeric field); `GradeBook.tsx`'s "possible" field and the malformed-URL case (`w=-5`, `w=0`) got the `onBlur`-clamp / fall-back-to-default half of the fix (see P2-5 below) — the per-row credits/score/weight fields inside `Gpa.tsx`'s and `GradeBook.tsx`'s loops were not converted to the uncontrolled-input hook (would need a sub-component split) and remain a known follow-up. Added a Playwright regression test that types "0.5" keystroke-by-keystroke and asserts the field reads exactly "0.5".
- **[P2-2] Negative/nonsensical verdict copy.** Every "needed" display value across all 4 tools is now floored at 0 (shows "0%"/"0" instead of "-40%", "-180%", "-17", "-50 of 100 points"). The points-based final now says explicitly "The final is worth 0 points, so it can't change your grade" instead of "-100 of 0 points (—%)". The "final replaces lowest test, already secured" message no longer claims the grade is locked at a fixed value ("your final would be the score that gets dropped either way") — it now correctly explains that scoring *above* your current lowest still raises your grade (a high final does still replace the lowest test).
- **[P2-3] Two-part final accepted weights totalling over 100%.** `weight1 + weight2 > 100` now shows an explicit "Check the weights" validation message instead of computing (and displaying) a wrong percentage.
- **[P2-4] Share button could copy a stale URL.** `useShare()` now accepts an optional `buildQuery()` callback; every tool's Share button uses it to build the URL directly from current state and flush it to the address bar synchronously before sharing/copying, instead of relying on the 250ms-debounced `history.replaceState` that a fast click could race past.
- **[P2-5] Converter Share buttons never encoded state; CGPA direction switch kept a nonsensical number.** `GpaToPercentage`, `PercentageToGpa`, `LetterToGpa` and `CgpaConverter` now read/write their value (and, for the CGPA converter, its direction) to/from the URL, hydration-safely (mount-effect pattern, same as the main tools). Switching the CGPA converter's direction now converts the displayed number through the formula instead of leaving the same digits to be reinterpreted under the other formula.
- **[P2-6] Germany and France scales were offered in the GPA averager** despite being unusable there (Germany is inverted — lower is better; France's per-band points are invented "mention" midpoints, not a real per-course GPA column). Added explicit `inverted`/`descriptive` flags to `scales.json` and a shared `isAverageable()` helper (used by both `Gpa.tsx` and every `/gpa-scale/{slug}/` page) that excludes them. The `/gpa-scale/germany-bavarian/` page's lead text no longer says "scale up to 1" (misleading for an inverted scale) — it now says "runs 1 (best) to 4 (fail) — lower is better".
- **[P2-7] Data and claim-accuracy problems:**
  1. Re-worded every "College-Board-style bands" reference (percentage-to-4.0 conversion, both converter pages, `grades.ts`) to "a common convention, not any single published standard" — the previous wording implied a citable, official table that doesn't match what's shown.
  2. Spain's `/10` bands were shown suffixed with "%" (they're /10 scores, not percentages) — added a `bandKind: 'score'` field and fixed the table header/cells and lead paragraph on `/gpa-scale/spain-10/`. Removed the secondary-only "Bien" band from the university-context averager entry (merged into a single Aprobado 5–6.99 band per RD 1125/2003) and relabelled the per-band "Points" column as GradeGoal's own representative mid-band values, not an official Spanish figure.
  3. Purdue: the previously-cited `purdue.edu/registrar/faculty-staff/grading/` page has no grade-point table (confirmed by fetching it). Found and re-cited an actual table (Purdue Polytechnic's Office of Academic Advising, "Academic Standards") and corrected the values it actually publishes — one-decimal weights (A- 3.7, B+ 3.3, …) rather than the two-decimal values (3.67, 3.33) previously guessed.
  4. Generic scales (no single citable institution) previously cited GradeGoal's own About page as their `source.url` — a self-citation. `source.url` is now `null` for all 8 generic entries, with a unit test (`tests/unit/scales.test.ts`) enforcing it never points back at this site.
  5. Softened the CBSE citation in the CGPA converter ("the Class 10/12 formula" → "CBSE's own convention, for its Class 10 CCE-era CGPA... other boards, universities and Class 12 marksheets often use a different formula").
  6. Fixed the "20 real grading scales — … UK classification, India CGPA, ECTS" claim on the home page, `/gpa-calculator/` and `PRODUCT.md`: it now says 20 researched scales total, 14 usable in the interactive averager, with the rest (including those three) as reference tables. Fixed `PRODUCT.md`'s "the site never makes a network request" claim to describe the opt-in analytics beacon accurately (see P3-2).
- **[P2-8] Grade-book item rows awkward on phones.** Redesigned the `<560px` grid: item name spans the full row; score / "/" / possible / remove now sit together on one compact row (`name / [score / possible] / ✕`) instead of the remove button stretching full-width and the "/" floating alone in its own cell.
- **[P3-1] Duplicate `BreadcrumbList` JSON-LD on every inner page.** `Breadcrumbs.astro` emitted one and each page's own `jsonLd` prop emitted a second, identical one. `Breadcrumbs.astro` is now pure navigation (no script tag); every page that renders it now supplies the `BreadcrumbList` once via `Base`'s `jsonLd` prop (about/contact/privacy/terms didn't do this before and got it added).
- **[P3-2] Privacy page was generic template text and didn't name the analytics processor.** Now names Supabase (Edge Functions) explicitly, states exactly what the beacon carries (path, referrer domain, device-width class, site id — no cross-visit identifier), and replaces the generic "files you open"/"history" phrasing with the actual `localStorage` keys (`gradegoal:gradebook:courses`, `gradegoal:gpa:semesters`) and what clearing them does.
- **Malformed negative/zero weights** (`w=-5`, `w=0`, `w1=0`, …) now fall back to the default weight instead of clamping up to 0.01, which used to distort the needed-score formula into values like "20088%".
- **JSON import**: capped at 2 MB before it's even read (was unbounded), and `drop` is now floored to an integer on import (previously could be a fraction).

### Not fixed (with reasons)

- **[P3-3] `/gpa-scale/{slug}/` page titles/queries.** Retitling all 20 pages to match the spec's "{university} gpa scale" pattern and fixing "worth 1 points" → "worth 1 point" grammar (the latter *is* fixed) touches SEO-sensitive copy across every scale page; left for a follow-up so it can get its own review rather than being bundled into this fix pass.
- **[P3-4] ARIA tab semantics without tab behaviour** (mode switches, course/semester lists, CGPA direction use `role="tablist"`/`role="tab"` with no `tabpanel`/`aria-controls`/arrow-key handling, and "+ New course" is a tab that performs an action). This is a real, if non-serious, a11y gap, but implementing the full WAI-ARIA tabs pattern (or switching to `aria-pressed` buttons) across 5 different tab-like UIs is a larger, higher-risk change than the time available in this pass allowed for without risking regressions elsewhere.
- **Per-row numeric fields** (GPA course credits; grade-book category weight/drop and item score/possible) still bind `value` directly to state rather than using the new `numberField.ts` uncontrolled-input hook (see P2-1) — they no longer *distort* values (the clamp-during-typing bug is fixed), but a mid-decimal keystroke could still occasionally reset the caret. Converting them needs each row to be its own sub-component (hooks can't be called inside `.map()`), which is a larger refactor than this pass's time allowed.
- **UT Austin citation** — the audit couldn't confirm the cited catalog page's table via fetch either; a repeat fetch attempt this session also returned an empty/nav-only page (likely JS-rendered content), but a broader search corroborates the existing data (A 4.00, A- 3.67, B+ 3.33, no A+). Left as-is rather than guessing further; a follow-up with an authenticated/rendered fetch could confirm it directly.
- **Minor edge cases**: Planner showing "0 credits" needed when prior credits are 0 (ambiguous rather than clearly wrong — not touched); no dedicated `@media print` stylesheet for the grade book's Print button (pre-existing, unrelated to this audit).
